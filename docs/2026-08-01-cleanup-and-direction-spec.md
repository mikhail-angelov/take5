# Take5 — Ревизия проекта, направление и целевая архитектура

**Дата:** 2026-08-01
**Статус:** направление зафиксировано (см. §2) — готово к планированию работ
**Автор ревью:** анализ кодовой базы на коммите `1fe3de0`

---

## 1. Резюме

Проект стоит и имеет здравое ядро: **extension-first** связка — человек руками
проходит флоу в Chrome-расширении, оно пишет семантический capture в JSON, CLI
нормализует его в replay-plan и (по замыслу) переигрывает в Playwright с записью
видео. Обнаружение флоу — за человеком, полировка/запись — за машиной.

Главная проблема: **репозиторий застрял между двумя продуктами**, а
задокументированное поведение не совпадает с реализованным. Есть значимый объём
неподключённого кода, дублирование контракта данных и устаревшая документация.

Тесты (58 шт.) зелёные, упаковка корректна, расширение декомпозировано аккуратно —
базовое качество высокое, проблема в направлении и «хвостах».

## 2. Зафиксированное направление

Проект содержал два несовместимых видения:

| Видение                                                                                  | Источник                                                | Решение                        |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------ |
| **Prompt-first**: автономный LLM-агент бродит по живому приложению и пишет видео         | `README.md`, `docs/prd.md`                              | ❌ отклонено, движок удаляется |
| **Extension-first**: человек захватывает флоу расширением → CLI реплеит и рендерит видео | `docs/superpowers/specs/2026-05-25-extension-first-...` | ✅ единственное направление    |

**Решение:**

1. **Extension-first** — единственное направление. Автономный LLM-агент
   (`agent.js`, `prompt.js`, `browser.js`) отклонён и удаляется (§3.1).
2. **Видео-полировку не пишем сами — берём `playwright-recast`** (MIT, v0.19.2).
   Он покрывает синтез курсора, авто-зум, классификацию темпа, субтитры и
   ffmpeg-рендер (пункты 1-6 из §6). Это соответствует принципу «established
   library over custom» — `converter.js` (`fluent-ffmpeg`) поэтому не нужен.
3. Наша ответственность — **захват (расширение) + детерминированный replay + AI-подписи**
   (пункты 7-8), то есть то, чего в recast нет.

Целевая архитектура и маппинг фич 1-8 — в §6.

## 3. Находки и требуемые изменения

### 3.1. 🔴 Ядро продукта не подключено (dead code)

Реальный путь исполнения — `cli.js → commands/run.js` — только валидирует
capture, строит plan и пишет `capture.json` + `plan.json`. Он **не** открывает
браузер, **не** пишет видео, **не** зовёт LLM. Весь «движок записи» из README/PRD
осиротел — ни один из этих файлов не импортируется из CLI:

| Файл               | Строк | Внешняя зависимость |
| ------------------ | ----- | ------------------- |
| `src/browser.js`   | 957   | `playwright`        |
| `src/agent.js`     | 111   | `openai`            |
| `src/annotator.js` | 221   | —                   |
| `src/converter.js` | 153   | `fluent-ffmpeg`     |
| `src/prompt.js`    | 36    | —                   |

Зависимости `playwright`, `openai`, `fluent-ffmpeg` встречаются **только** в этих
файлах, то есть шипнутый CLI тащит их впустую (`docs/AI_LEARNED.md` это
подтверждает: «run command produces replay artifacts only»).

**Изменение:**

- **Удалить** `src/agent.js`, `src/prompt.js` (автономный LLM-агент отклонён),
  `src/converter.js` (заменяется `playwright-recast`) и их тесты.
- **`src/browser.js`** — не подключать as-is (957 строк, заточен под агента).
  Логику вождения Playwright переписать в компактный `replay-runner.js` под
  детерминированный replay плана (§6). Из старого файла переиспользовать только
  маппинг «семантическое действие → Playwright-вызов».
- **`src/annotator.js`** — оценить на переиспользование для позиционных callout-ов
  (пункт 7): его in-page overlay пересекается с `extension/annotation-overlay.js`.
  Свести к одному источнику, не держать две реализации оверлея.
- **`package.json`:** убрать `fluent-ffmpeg`; добавить `playwright-recast`;
  оставить `playwright`; `openai` оставить только под AI-подписи (пункт 8),
  иначе удалить.

### 3.2. 🔴 Дублирование контракта данных

`src/capture-schema.js` ≡ `extension/capture-schema.js` — **байт-в-байт**
идентичны (166 строк). То же с `plan-generator.js` (177 строк). Это контракт
между расширением и CLI; он разъедется при первом изменении с одной стороны.

**Изменение:**

- Вынести общий контракт в единый источник (`shared/capture-schema.js`,
  `shared/plan-generator.js`).
- CLI импортирует напрямую. Расширение — classic-скрипт (коммит `9f4cc3f`),
  поэтому нужен билд-шаг (esbuild/rollup) **или** генерация файла расширения из
  общего источника. Ручное дублирование запрещено.

### 3.3. 🟠 Мусор в репозитории

- `test.md`, `test2.md`, `test3.md` в корне — черновики (в `.gitignore` через
  `test*`, но лежат в рабочей копии). Удалить.
- `music.mp3` (3.3 МБ), `take5-output/`, `take5-output-test/` — артефакты прогонов.
  Игнорируются, но замусоривают рабочую копию. Почистить.
- `.DS_Store` (корень, `.worktrees`) — удалить физически.
- `extension/README.md` — заглушка «Placeholder directory». Заполнить или убрать.

### 3.4. 🟠 Устаревшая документация

`README.md` и `docs/prd.md` описывают старый prompt-first продукт (LLM бродит по
приложению, пишет видео) — противоречат spec и реальному коду.

**Изменение:** переписать под extension-first: расширение захватывает флоу; `run`
сейчас нормализует capture в артефакты (`capture.json`, `plan.json`);
Playwright-replay — состояние roadmap, а не текущее поведение.

### 3.5. 🟡 Мелкие дефекты качества

- **Нет линтера/форматтера:** `browser.js`/`annotator.js` — двойные кавычки и иной
  стиль, остальной `src/` — одинарные. Добавить ESLint + Prettier и прогнать.
- **Провайдер LLM зашит** (актуально для фичи 8): в удаляемом `agent.js` хардкод
  `baseURL: https://api.deepseek.com` и `model: deepseek-chat`. Для AI-подписей
  сделать провайдер/модель конфигурируемыми через env, не хардкодить.
- **`.env.example`/README** упоминают `DEEPSEEK_API_KEY` для старого агента —
  привести к реальному использованию (или убрать, пока фичи 8 нет).

5. **[🟡]** Добавить ESLint + Prettier, привести стиль к единому (§3.5).

**Фаза B — целевой пайплайн видео (§6):**

- ✅ `src/replay-runner.js`: исполняет `plan.json` в headless Chromium, инжектит
  позиционные callout-ы (фича 7), пишет `trace.zip` + `.webm`.
- ✅ `src/render.js`: обёртка над `playwright-recast` (speedUp + autoZoom +
  cursorOverlay + clickEffect → `demo.mp4`). Фичи 1-5.
- ✅ Подключено к `commands/run.js` за флагом `--render`. Юнит-тесты на чистые
  хелперы + проверено end-to-end (герметичный `file://`-фикстур → валидный H.264 1080p).
- ✅ **Фичи 6+8 (наррация/субтитры)** — `src/captions.js`: `describeStep` строит
  подпись на каждый значимый шаг плана; recast таймит и чанкит их через
  `.subtitles(textFn)` (фича 6) и прожигает. `--ai-captions` натурализует их
  одним LLM-вызовом (feature 8, OpenAI-совместимый через `fetch`, без SDK;
  fallback на детерминированные при отсутствии ключа/ошибке). Проверено e2e:
  подписи ложатся 1:1 на значимые действия, не съедаются callout-ами/assert-ами.

**Найдено при интеграции recast (важно для §6.2):**

- `autoZoom()` **требует** предшествующего `subtitles*()` — зум привязан к окнам
  субтитров. Без осмысленного SRT ставим `subtitlesFromTrace()` только ради окон
  зума и **не прожигаем** их (`burnSubtitles:false`).
- Callout-hold (`waitForTimeout`) классифицируется recast как idle и ускоряется —
  позиционные callout-ы (фича 7) могут мелькать на реальном контенте. Прожжённые
  наррация-субтитры (6+8) читаемость демо закрывают; тюнинг длительности
  callout-hold vs idle-speed — открытый вопрос, если понадобится.

**Критерий готовности Фазы A:** `npm test` зелёный; `dependencies` содержит
только используемые пакеты; ни одного файла с нулём входящих импортов вне точек
входа; README описывает фактическое поведение; схема в одном экземпляре.

**Критерий готовности Фазы B:** `take5 run <capture> --render` из
`fixtures/easycad-screencast-capture.json` производит воспроизводимый `.mp4` с
курсором, авто-зумом, вырезанными простоями и позиционными подписями.

## 6. Целевая архитектура replay + рендер

### 6.1. Пайплайн

```
Chrome-расширение          take5 CLI (commands/run.js)
──────────────────         ────────────────────────────────────────────────
capture (JSON)  ──export──►  loadCaptureBundle
                             createReplayPlan        → plan.json
                             replay-runner (Playwright, headless)
                               • исполняет шаги плана
                               • инжектит позиционные callout-ы в DOM (фича 7)
                               • пишет trace.zip + video.webm
                               • (roadmap) captions.srt из аннотаций / AI (фича 8)
                             render (playwright-recast)
                               Recast.from(runDir)
                                 .speedUp(...)          ← фича 4
                                 .subtitlesFromTrace()  ← окна для зума (не прожиг)
                                 .autoZoom()            ← фича 3 (из координат trace)
                                 .cursorOverlay()       ← фичи 1,2
                                 .clickEffect()         ← ripple
                                 .render({format:'mp4'}).toFile()
                                                        → demo.mp4 (фича 5)
```

**Уточнено при реализации:** зум делаем через `autoZoom()`, который берёт
координаты **прямо из fill/click-действий в trace** — это проще, чем изначально
запланированный `zoom-report.json` + `enrichZoomFromReport()`, и не требует
вручную считать rect→доли (принцип «простейшее решение»). Ограничение recast:
`autoZoom()` требует предшествующего `subtitles*()` (зум привязан к окнам
субтитров) и пропускает окна короче 500 мс. Поэтому без осмысленного SRT ставим
`subtitlesFromTrace()` только ради окон и **не прожигаем** их (`burnSubtitles:false`).
`subtitlesFromSrt()` для реальных подписей (фичи 6/8) уже поддержан через `srtPath`.

### 6.2. Маппинг фич 1-8

| #   | Фича                                         | Кто делает | Как                                                                 |
| --- | -------------------------------------------- | ---------- | ------------------------------------------------------------------- |
| 1   | Синтез курсора (glide + held-approach)       | **recast** | авто из click/selectOption в trace                                  |
| 2   | `glideAndClick` / `glideAndType` тайминг     | **recast** | внутренняя анимация оверлея                                         |
| 3   | Авто-зум к элементу с easing                 | **recast** | `.autoZoom()` из координат fill/click в trace (окна ≥500 мс)        |
| 4   | Классификация темпа / вырезание простоев     | **recast** | `.speedUp({duringIdle, duringUserAction})`                          |
| 5   | FFmpeg-рендер (курсор/зум/субтитры запечены) | **recast** | `.render().toFile()`                                                |
| 6   | Punctuation-aware чанкинг подписей           | **recast** | `.subtitlesFromSrt()` (наш SRT)                                     |
| 7   | Позиционные callout-карточки «near element»  | **Take5**  | инжект оверлея в DOM во время replay (запекается в видео до recast) |
| 8   | AI-автоподпись шага                          | **Take5**  | LLM генерирует текст подписи из семантики шага → SRT/аннотация      |

Разделение подписей: **позиционные callout-ы** (пункт 7) привязаны к элементу и
инжектятся в страницу во время replay; **глобальная наррация/субтитры** (пункты
6, 8) идут через recast снизу/сверху кадра. Это две разные поверхности, не дублируют друг друга.

### 6.3. Новые артефакты рана

К `capture.json` + `plan.json` при `--render` добавляются: `trace.zip`,
`video.webm` (сырая запись, детерминированное имя), `demo.mp4` (готовое видео),
плюс служебные recast-файлы (`recast-report.json`, `demo.srt/.vtt`, `screenshots/`).
`zoom-report.json` **не создаётся** — зум идёт из trace через `autoZoom()` (§6.1).
`captions.srt` появится со срезом фич 6/8. Промежуточные артефакты остаются на
диске для отладки и перерендера без повторного прогона браузера.

### 6.4. Зависимости и требования

- `playwright-recast` (MIT, v0.19.2) — deps лёгкие (`fflate`, `zod`,
  `@modelcontextprotocol/sdk`), не тянет свой ffmpeg.
- **Требуется `ffmpeg` + `ffprobe` в PATH** (было опционально — становится
  обязательным для `--render`; без него `run` останавливается на артефактах).
- `playwright` — остаётся (вождение браузера в replay).

## 7. Конкурентный ландшафт (обоснование)

Рынок делится на два лагеря, Take5 стоит на стыке:

- **Интерактивные HTML-демо** (Arcade, Storylane, Supademo, Navattic): расширение
  ловит клики → кликабельный HTML-walkthrough. Заимствуем: захват семантики
  расширением, **AI-автоподпись шага** (пункт 8).
- **«Киношные» скринрекордеры** (Screen Studio, FocuSee, Cursorful; опенсорс
  Recordly, OpenScreen): авто-зум, сглаживание курсора, вырезание простоев.
  Эти приёмы забирает `playwright-recast`.
- **Прямые близнецы по архитектуре** (code-driven, «не устаревает в CI»):
  `playwright-recast`, ScreenCI, NextDemo, AIOProductOS Studio.

**Дифференциатор Take5:** против HTML-демо — настоящее **видео**; против
скринрекордеров — **семантический захват + детерминированный перерендер в CI**.
Держим оба свойства одновременно — этого нет ни у кого из массовых игроков.
